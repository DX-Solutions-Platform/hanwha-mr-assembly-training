# HANWHA · MR 조립 교육

PC 브라우저와 Meta Quest 3 브라우저에서 쓰는 조립 교육입니다. 확정된 시안(Demo 1, HUD Prototype, Complex Explode 등)을 Next.js로 옮겼습니다.

## 실행
```bash
npm install
npm run dev              # http://localhost:3000 → 프로젝트 안내 → 확인 → /training
npm run build && npm start
npm run typecheck        # 타입 검사
npm run lint
npm run test:startup     # 시작 화면·모바일 안내·3D 로더 재시도 검사 (개발 서버 실행 중)
npm run test:upload-dev  # PDF 부품표·치수 추출 검사 (-- --browser 추가 시 개발 서버에서 화면 검증)
npm run test:part-review # 부품 묶음·보정·확정·저장 검사 (-- --browser 추가 시 화면 검증)
npm run test:step-upload # 실제 STEP 변환·부품 연결·저장 검사 (-- --browser 추가 시 3D 화면 검증)
npm run test:pdf-model   # PDF 기반 플랜지 생성·수정·저장·GLB 검사 (-- --browser 추가 시 화면 검증)
npm run test:real-upload # 실제 /training/upload의 PDF 분석·3D 연결·파일 내용 변경·미지원 입력 검사
npm run test:assembly    # 조립품 계층·위치·결합·저장 검사 (-- --browser 추가 시 실제 편집 화면 검증)
npm run test:upload-usability # 하단 버튼·메뉴·키보드·실시간 편집·저장 복원 실제 화면 검증
npm run test:bulk-review # PDF 자동 채움·부품표 일괄 입력 검사 (-- --browser 추가 시 실제 파일·저장 복원 검증)
npm run test:intro-layout # 시작 안내 6단계 × 8가지 창 크기·가로 넘침·이동 검사
npm run test:lint-regressions # 기존 3D 분해·제품 전환·교육장 시점·일시정지 검사
npm run test:ocr          # OCR 좌표·공백·중복·공차 후보 검사 (-- --browser 추가 시 실제 스캔 PDF 업로드·저장 복원 검증)
npm run test:load        # 부하 테스트 (npm start 실행 중일 때)
```
Node 20.9 이상이 필요합니다. 전달본에는 `package-lock.json`을 포함했습니다. 동일 버전 재설치에는 `npm ci`를 사용할 수 있습니다.

## 3D 모델
- 현재 시안 이식 화면은 원본 도형·조명·렌더링 코드와 로컬 three.js r149를 사용합니다. 아래 데이터 기반 모델/렌더 예산은 기존 `SceneCanvas` 구현에 해당합니다.
- `src/data/models/*.ts`의 데이터로 모델을 만듭니다. 반복 부품(볼트, 블레이드, 좌석)은 InstancedMesh 1개로 그립니다.
- 실제 GLB로 바꿀 때는 같은 구간(sectionIndex) 정보를 유지한 채 `buildModel`을 GLB 로더로 교체합니다.
- GLB는 gltf-transform으로 Draco/Meshopt + KTX2 압축 후 `public/models`에 둡니다. `hammer.glb`(14MB)는 배포 전에 압축이 필요합니다.

## 현재 이식 상태
- 펌프 선택/분해/준비/안전/BOM/실습/12 N·m 체결/리포트를 원본 값으로 반영했습니다.
- 업로드 3단계, 세부 카드, 스텝 스툴 4카드·19단계·6 N·m 체결, 복합 분해, 단독 HUD, 디자인 가이드를 원본에서 React/styled-components로 이식했습니다.
- 원본 장면은 같은 three.js r149를 사용합니다. 생성 모듈과 원본 해시는 `src/features/reference-pages/generated`에 있습니다.
- 실제 도면 분석 API, 서버 기록 전송/DB, 원본에 없는 펌프 중부·하부·최종 결합 실습은 추가하지 않았습니다.
- `/training/upload-dev`는 /training/upload와 같은 실제 분석 화면을 사용합니다. PDF.js로 모든 페이지(최대 200쪽/50 MB)의 이미지·텍스트 좌표를 읽고, 한국어·영어·프랑스어 표 제목을 기준으로 부품표 행을 추출합니다. 지름·반지름·나사·각도·공차·단위가 있는 길이 표기와 단독 수치 후보를 구분하며 출처 페이지·위치를 JSON에 보존합니다. 원문 확인이 필요하며, 임의 PDF의 일반적인 3D 복원·조립 순서 및 토크 확정·교육 생성은 이 화면의 구현 범위에 포함되지 않습니다.
- 큰 이미지 영역에 PDF 글자가 부족하면 **한국어·영문 OCR**을 자동 실행합니다. 일반 텍스트 PDF와 작은 로고는 OCR을 생략하며, 텍스트·스캔이 섞인 PDF도 페이지·이미지 영역을 기준으로 처리합니다. 기존 PDF 글자와 겹치는 OCR 단어는 중복 추가하지 않습니다. 잘못된 글자층이 들어 있는 PDF는 **더보기 → OCR로 다시 읽기**로 이미지 기준 재인식을 할 수 있습니다.
- OCR은 브라우저 Worker와 로컬 Tesseract.js 7.0.0 / core 7.0.0 / 한국어·영문 best_int 모델로 처리합니다. 문서·이미지를 외부 OCR·LLM 서비스에 업로드하지 않습니다. `npm install`의 postinstall에서 실행 파일·모델·라이선스를 `public/vendor/ocr-7.0.0`에 복사합니다. 배포 시 이 정적 파일을 포함해야 하며 `node scripts/sync-ocr-runtime.cjs`로 재생성할 수 있습니다. OCR 렌더링은 최대 긴 변 3,508px·800만 화소·300dpi이며, 한 페이지의 준비·인식은 120초로 제한합니다. 작업 완료·중지·파일 교체·실패 시 Worker와 이미지를 정리합니다.
- OCR 단어의 위치·신뢰도로 기존 부품표·치수 추출을 실행해 품명·수량·재질을 검토 입력값에 자동 반영합니다. 한국어 단어 사이의 공백은 인식한 문장에 맞춰 보존하고, 일부 한글 셀·애매한 기호는 이미지에서 한 번 더 읽습니다. OCR 출처와 낮은 신뢰도를 표시하며 **보완** 필터에도 반영합니다. 잘못 읽힌 공차(`100 £0.1 mm` 등)는 `0.1 mm`라는 확정 길이로 분리하지 않고 원문 전체를 검토 후보로 남깁니다. 원문에 없는 정보·단위·수량은 추정하지 않으며, OCR 결과도 자동 확정하지 않습니다.
- OCR 준비·인식 진행 상태를 처리 내역에서 보여 줍니다. 빈 스캔·실행 실패는 성공한 추출처럼 표시하지 않고 원문 확인·재분석을 안내하며 다른 페이지의 결과는 보존합니다. 검토 저장·JSON 내보내기에는 원문 값·OCR 출처 좌표·신뢰도·엔진 정보와 편집값을 보관합니다. 같은 PDF를 다시 올리면 재인식 후 저장한 검토·확정·치수 연결을 복원합니다. 기존 v1/v2 검토 파일도 계속 읽습니다.
- OCR 검증은 숨은 텍스트가 없는 영문·한국어 스캔, 텍스트/이미지 혼합, 빈 스캔으로 수행합니다. `scripts/create-ocr-fixtures.py`가 Windows 글꼴과 Pillow·reportlab·pypdf로 실제 이미지 PDF를 생성합니다. `OCR_PYTHON`으로 해당 Python을, `OCR_FIXTURE_DIR`로 검증 PDF 폴더를 지정할 수 있습니다. `npm run test:ocr -- --browser`는 실제 인식·자동 입력·원문 강조·보정·확정·저장·재업로드 복원·JSON 입출력·중지/교체·실패/재시도·Worker 종료를 검사합니다. 흐린 스캔이나 작은 글자, 특수 공차·기호는 원문 대조와 보정이 필요합니다.
- 분석 완료 후 **부품 검토·보정**에서 동일 부품번호를 묶어 확인합니다. 반복 수량은 합산하지 않으며, 원문마다 다른 값은 직접 선택·보정합니다. 원문과 추출값은 보존하고 편집값을 별도로 저장합니다. 치수는 부품에 직접 연결하거나 입력하고, 치수가 없는 경우에도 확인 표시가 필요합니다. 필수 정보·단위를 검증한 뒤 부품별로 검토 확정하며, 수정하면 확정이 해제됩니다.
- 원문에 품명이 없으면 `미지정 부품 001234`처럼 부품번호로 **자동 임시 품명**을 채웁니다. 번호도 없으면 원문 항목 식별자로 구분합니다. 임시 표시와 이름은 저장·복원·검토 JSON에 유지되며, 이 이름으로 검토 확정하거나 직접 수정할 수 있습니다. 부품표를 일괄 입력하면 덮어쓰기를 선택하지 않아도 임시 품명이 실제 품명으로 교체됩니다. 직접 입력한 품명은 보호하고, 원문 품명끼리 충돌하면 자동 이름으로 감추지 않습니다. 원문 근거에는 임시 이름을 쓰지 않으며 수량·재질은 임의 생성하지 않습니다.
- PDF 분석 후 품명이 비어 있는 미확정 부품은 **로컬 Qwen 형상 추정**을 자동 실행합니다. 부품번호가 표나 명시적 번호 라벨에 있고 한 종류만 연결되는 페이지에서 글자 영역을 가린 뒤, 형상 영역을 잘라 처리합니다. 플랜지·볼트·너트·와셔·베이스판·축 후보만 채우고, 여러 부품이 섞인 페이지와 판단이 불명확한 경우에는 임시 이름을 유지합니다. 검토 화면의 **판단 영역 보기**는 모델에 사용한 영역을 강조합니다. 모델 이름·판단 문구·좌표는 검토 저장과 JSON에 포함되며, 품명을 직접 바꾸면 형상 추정 표시가 해제됩니다.
- 형상 추정은 웹앱이 실행되는 PC의 `127.0.0.1:11434` Ollama에 설치된 `qwen3-vl:8b`를 사용합니다. 모델은 배포 전에 설치하고 폐쇄망 운영 시 Ollama를 로컬 전용으로 설정합니다. PDF 원본 대신 잘라낸 이미지를 순차 요청하며, 요청당 최대 120초입니다. 모델이 꺼져 있거나 요청이 실패하면 기존 PDF 추출 결과를 검토할 수 있고, **더보기 → 형상 분석 다시 시도**를 사용할 수 있습니다.
- 비교할 때는 저장된 검토값의 영향을 피하도록 별도 브라우저 세션에서 `/training/upload?qwen=off`와 기본 주소에 같은 PDF를 올립니다. `scripts/create-qwen-shape-fixture.py`는 비교용 합성 PDF를 만들고, `node scripts/verify-qwen-shape.cjs <PDF 경로>`는 두 방식을 세 번씩 실행해 품명 일치·오분류·보류와 처리 시간을 기록합니다. 이 검증에는 개발 서버와 로컬 Ollama가 필요합니다.
- 기본 업로드는 Ollama의 **Qwen3-VL 8B**를 사용합니다. 8B가 형상 판단을 보류한 부품을 선택하면 **27B로 다시 분석**이 표시됩니다. 앱은 8B를 GPU에서 내리고 WSL2의 vLLM을 시작합니다. 다음 8B 요청에서는 vLLM을 먼저 종료합니다. `?qwen=awq`는 전체 도면을 27B로 비교할 때 사용합니다.

- 연결도 **검토 결과 저장**과 검토 JSON(v2)에 포함됩니다. 기존 v1 검토 JSON도 읽습니다. 저장되는 것은 원본 STEP의 SHA-256·형상 식별 정보와 연결이며 원본 파일·3D 메시 자체는 저장하지 않습니다. 다시 열 때 같은 PDF와 STEP을 올리면 복원됩니다. 다른 STEP은 기존 연결을 적용하지 않으며, 명시적으로 **현재 STEP으로 다시 시작**할 때만 이전 연결을 지웁니다.
- STEP 제한은 25 MB·1,000개 형상·100만 삼각형·변환 120초입니다. 중지·재시도·파일 교체를 지원하고, 교체 실패 시 이전 미리보기와 연결을 보존합니다. 외부 부품 파일을 참조하는 조립품은 부품을 포함한 단일 STEP으로 내보내야 합니다. 메시가 BOM 부품과 일대일로 대응한다고 가정하지 않으며, 하나로 합쳐진 STEP은 분리된 조립품으로 다시 내보내야 부품별 연결이 가능합니다. 3D 화면의 단위는 mm이며 형상 표시는 테셀레이션 결과입니다.
- 코드 검사는 수정하는 앱 소스에 적용하며 `public/vendor/**`의 외부 배포 라이브러리는 제외합니다. 이전 오류 64건은 외부 라이브러리 검사 47건과 앱 소스 17건으로 분류했고, 앱의 렌더 중 참조 갱신·상태 전환·3D 객체 갱신·리포트 시간·테마 타입을 수정했습니다. 시작 안내의 움직이는 이미지 영역도 포함 영역 안에 제한하고, 높이 900px 이하에서는 글자와 간격을 조절해 좁은 창의 가로 스크롤을 제거했습니다.
- STEP 런타임은 고정 버전 occt-import-js@0.0.23입니다. 설치 후 scripts/sync-step-runtime.cjs가 JS·WASM·라이선스를 public/vendor/occt-0.0.23에 복사합니다. npm ci --ignore-scripts를 사용했다면 node scripts/sync-step-runtime.cjs를 별도로 실행하세요. 실제 STEP 검증 파일은 의존성에 포함된 upstream 테스트 파일을 사용하며 제품의 기본 예제로 등록하지 않습니다.
