# 원본 시안 이식 현황 · 2026-11-03

기준은 인수인계의 README/01~05와 reference 원본입니다. 원본 HTML, support.js 또는 iframe을 앱에 넣어 실행하지 않습니다. 템플릿은 정적 React TSX로, DOM 스타일과 hover는 styled-components로 변환했습니다. 원본 장면·상태 로직은 별도 생성 모듈에 보존했습니다.

## 검증

- 프로덕션 빌드, 타입 검사, 이번 변경 파일의 ESLint 통과.
- 펌프 체결식·리포트 계산 회귀 검사는 기존 `verify-assembly.cjs`, `verify-report.cjs`를 유지합니다.
- `verify-reference.cjs`로 원본 6개 파일의 SHA-256 및 12개 고정 데이터 필드를 대조했습니다. 즉시 병합되는 원본 상태 계약, React 노드 삽입, SVG 변환도 검증했습니다.
- 브라우저에서 예시 PDF→검토→교육 생성→커스텀 카드→스툴 입장을 확인했습니다.
- 스툴 프레임 A/B·연결대를 실제 드래그로 장착하고 볼트를 삽입했습니다. 역회전 0, 시계 회전의 저항·6 N·m 도달·다음 볼트 전환을 확인했습니다.
- 최종 점검 카드를 직접 열어 윗판 누르기→완료 리포트 표시를 확인했습니다. 19단계 전체를 한 번에 끝까지 반복한 검증은 하지 않았습니다.
- 여객기/스마트폰 전환·공정 선택, 단독 교육장의 준비·공구 안전·망치 3D, 가이드 스크롤을 확인했습니다.
- 통합 펌프 실습에서도 V→토크 렌치 안전 수칙과 원본 망치 3D를 확인했고, 해당 검증 탭의 콘솔 오류/경고는 없었습니다.
- 프로덕션 7개 화면 × HD/FHD/QHD/4K, 28개 조합에서 16:9 화면 외곽 크기가 일치했습니다. 근거는 전달 파일 `browser-verification.json`입니다.
- 자동화 브라우저에서 초기화/백그라운드 구간에 1 FPS 저점이 섞였습니다. 이 환경의 짧은 FPS 표시는 성능 합격 근거로 사용하지 않았습니다. CPU 4배/6배 감속의 3회 부하 테스트와 Quest 3 실기기 검증은 미실시입니다.

## 원본대로 남긴 제한

- 유압 펌프 중부·하부·최종 결합의 실제 조립 로직은 원본에 없습니다. 상부 이후 안내를 유지합니다.
- 차량·드론은 원본처럼 준비 중입니다.
- 도면 분석은 원본의 스텝 스툴 예시 생성입니다. 임의 도면의 실제 부품 인식·모델 생성 API는 없습니다. PDF 자체의 렌더링/텍스트 읽기는 동작합니다.
- 교육 저장은 sessionStorage이며 실제 서버 DB/담당자 전송은 없습니다. 리포트의 전송 문구는 원본 표시입니다.
- Training Menu는 커스텀 스툴 카드에서도 제목이 `유압 펌프 · 조립 카드`로 고정되어 있습니다. 원본의 고정 문구를 바꾸지 않았습니다.
- 인수인계 README의 최종본 8개를 기준으로 삼았습니다. 함께 포함된 이전 참조 `Demo A HUD`/`Explode Preview`는 별도 신규 화면으로 추가하지 않고, 남아 있는 링크는 현재 교육장/복합 분해 라우트로 연결했습니다.
- GLB/PDF/폰트의 외부 배포 가능 여부는 이식 승인으로 확정할 수 없어, 별도 라이선스 확인 항목으로 유지합니다. 이번 작업은 로컬 앱에만 반영했습니다.

## 유지보수

`src/features/reference-pages/generated`는 원본에서 생성한 파일입니다. 비정형 원본 로직을 보존하기 위해 해당 파일만 타입/린트 자동 교정 대상에서 제외했습니다. 런타임·저장소·라우트 연결과 기존 펌프 실습은 타입 검사합니다.

```powershell
python -X utf8 scripts/port-reference.py --source ../reference
node scripts/verify-reference.cjs ../reference
node scripts/verify-assembly.cjs
node scripts/verify-report.cjs
npm run typecheck
npm run build
```

원본 `support.js`의 동기 상태 병합은 `PortedLogic.updateReferenceState`로 이식했습니다. 라우트, 로컬 리소스 경로, React 생명주기 및 정리 처리 외에는 시각·모델·체결 데이터를 바꾸지 않았습니다. 공구 GLTF 로더도 같은 r149를 사용하며 별도 three 모듈을 불러오지 않습니다.

전달본의 `package-lock.json`은 현재 의존성 버전을 고정합니다. 전체 저장소의 린트 통과를 뜻하지 않으며, 위 ESLint 검증은 이번 이식 파일과 연결 파일에 한정됩니다. FPS 표시의 URL 플래그는 서버/클라이언트 초기 스냅샷을 구분하도록 정리했고, 측정식·디자인 값은 유지했습니다.
