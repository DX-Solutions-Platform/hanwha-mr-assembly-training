# 부하 테스트 리포트

## 1. 자동 테스트 (개발 PC에서 실행)
`npm run build && npm start` 후 다른 터미널에서 `npm run test:load`를 실행합니다.

- 화면 8개: 교육 선택 · 공정 선택(분해) · 교육장(한 화면) · 교육장(단독) · 여객기·스마트폰 · 도면 업데이트 · 세부 조립 카드 · 스텝 스툴 교육
- 해상도 4개: HD 1280×720 · FHD 1920×1080 · QHD 2560×1440 · 4K 3840×2160
- 기기 조건 2개: 저사양 PC(CPU 4배 감속) · Quest 3 근사(CPU 6배 감속)
- 조건마다 3회 이상 (`RUN_COUNT`, 최소 3)
- 통과 기준: 평균 45fps 이상, 1% 저점 30fps 이상
- 결과는 `docs/load-test-result.json`에 저장되고, 하나라도 기준에 못 미치면 실패로 끝납니다.
- 헤드리스 모드는 소프트웨어 렌더링이라 GPU 성능이 반영되지 않습니다. 실제 GPU로 재려면 `HEADLESS=0 npm run test:load`로 실행합니다.

### 이번 이식 검증 상태

프로덕션 7화면 × HD/FHD/QHD/4K의 28개 조합에서 16:9 화면 경계를 확인했습니다. 자동화 브라우저의 초기/비활성 구간에 1 FPS 저점이 섞여 FPS 합격 판정에는 사용하지 않았습니다. CPU 감속 2조건 × 3회 부하 테스트 및 Quest 3 실기기 측정은 아직 실행하지 않았습니다. 위 자동 테스트 코드는 안전 수칙과 BOM을 실제 통과한 실습 단계에서 측정하도록 갱신했습니다.

## 2. 시안 사전 측정 (2026-11-03 · 디자인 시안 파일 · 3회)
Next.js 빌드가 아니라, 이 프로젝트가 옮겨 온 시안 파일을 미리보기 창(924×540, dpr 1)에서 4초씩 3회 측정한 값입니다. CPU 감속은 적용하지 못했습니다.

| 화면 | 1회 | 2회 | 3회 | 1% 저점 | JS 메모리 |
|---|---|---|---|---|---|
| 교육 선택 (Demo 1) | 216fps | 216fps | 216fps | 141fps | 21–24MB |
| 공정 선택·분해 (Demo 1) | 216fps | 216fps | 216fps | 141fps | 23–35MB |
| 교육장 (HUD Prototype) | 191fps | 216fps | 216fps | 141fps | 85–103MB |
| 여객기 분해 (Complex Explode) | 216fps | 216fps | 216fps | 141fps | 19–41MB |

- 216fps는 측정 환경의 화면 갱신 상한으로 보입니다. 모든 화면이 상한에 붙어 있어 이 측정만으로는 여유분을 알 수 없습니다.
- 교육장은 첫 회에 191fps로 한 번 떨어졌고, 메모리가 다른 화면보다 큽니다. 망치 GLB(14MB) 때문으로 보이며 압축 대상입니다.

## 3. Quest 3 실기기 확인 (직접 진행)
1. 같은 네트워크에서 PC의 `npm start` 주소를 Quest 브라우저로 엽니다.
2. 주소 뒤에 `?perf=1`을 붙이면 오른쪽 위에 FPS와 1% 저점이 표시됩니다. 예: `/training?perf=1`
3. 화면마다 30초 이상 조작하며 3회 기록합니다. 기준은 평균 45fps 이상(72Hz 기준), 1% 저점 30fps 이상입니다.
4. 기존 `SceneCanvas`에는 렌더 배율 1 → 0.85 → 0.7 → 0.55의 자동 조절이 있습니다(`src/lib/renderBudget.ts`). 원본 r149로 이식한 장면은 시안 배율을 유지하므로 이 조절이 적용되지 않습니다.
